# GDUTNIC 排班签到

网络服务协会的值班排班与签到系统。普通成员用姓名和密码登录，查看自己的排班并签到；管理员在管理端维护每日/每周/特殊排班、账号权限、外勤登记与考勤统计。界面保留 Material You 风格。


## 一行部署

前提：已下载本项目，安装 Python 3.10+（含 `venv`）和带 Compose 插件的 Docker，并启动 Docker 服务。下面命令均在项目根目录执行。

**Linux / macOS：**

```bash
python3 -m server.init_data && docker compose --env-file data/.env up -d --wait mysql && bash start.sh
```

**Windows（CMD）：**

```bat
python -m server.init_data && docker compose --env-file data/.env up -d --wait mysql && start.bat
```

命令会初始化 `data/`、生成随机数据库密码、启动并等待 MySQL 就绪，再创建 `.venv`、安装依赖并启动应用。任一步骤失败都会停止后续步骤。重复执行保留现有数据库、配置和已修改的用户密码；更新代码前先停止正在运行的应用。

- 成员入口：`http://127.0.0.1:50025/`；其他设备使用服务器 IP 和端口 `50025`。
- 管理员入口：复制启动日志打印的随机路径，首次进入设置**原始管理员**密码。
- 用户端和管理员登录框均可点击眼睛图标显示 / 隐藏密码；图标随 `icon/` 一起部署，不依赖 `parment/`。
- MySQL 在后台运行并配置为自动重启；应用在当前终端前台运行，按 `Ctrl+C` 停止。需要长期运行时，将应用交给系统服务或进程管理器托管。
- 使用已有或远程 MySQL 时，先配置 `data/.env`，然后执行 `bash start.sh`（Windows 用 `start.bat`），无需启动本地 MySQL 容器。

## 项目各部分使用方法

### 启动与首次配置

```bash
python3 -m server.init_data   # Windows 可用 python；无需先安装依赖
# 自动生成 data/.env 和随机数据库密码；远程数据库请编辑 data/.env
docker compose --env-file data/.env up -d --wait mysql
./start.sh                    # Windows 用 start.bat
```

启动日志会打印管理员地址（形如 `http://127.0.0.1:50025/a8clrf3j`）。首次打开该地址会创建管理员，首个管理员自动获得全部权限。

### 成员端（`/`）

1. 用姓名和密码登录，默认初始密码 `gg2017`。
2. 「当前排班」只显示本人在当天的班次；在班次开始前「提前打卡」分钟内按钮变为可点。
3. 点击签到后记录到岗时间；若下一班与本班首尾相接（1→2、3→4），会自动一并签到。
4. 左侧「外勤管理」中点击按钮登记本月外勤，成功后按钮固定为「登记完成」。
5. 「排班列表」可按周浏览所有已生成排班，完整显示值班人员姓名；不显示考勤状态，卡片保持统一颜色。此入口需要单独授予「排班列表」权限，不随「当前排班」权限自动开放。
6. 左侧底部可修改密码；修改后持久保存，重启不会恢复为初始密码；会话 4 小时后过期。

### 管理端概览

- 固定显示本月出勤率、迟到数、旷班数。三个统计药丸保持单行，内容过长自动撑宽，空间不足时整组隐藏。
- 时间轴显示当前值班与人员姓名；下方周历按真实班次显示第一至第四班，缺班留空。只有从「特殊排班」新增的班次才进入特殊排班行；该周有特殊排班时才显示，与第四班间隔一个普通班次行高度，每天按开始时间纵向排列。
- **周排班翻页与整周删除**：周历两侧的箭头查看上一周 / 下一周，范围覆盖有排班的最早到最晚一周；到边界时对应箭头变灰禁用，中间没有排班的周仍可翻到。翻到其他周时标题变为「周排班」，并出现「回到本周」。
- **删除整周排班**：按钮删除当前显示这一周（周一至周日）的全部班次。需在确认卡片输入「删除本周排班」；该周已签到的记录会先归档到出勤历史，仍可在统计中查到，每周模板与账号不受影响。这一周没有排班时按钮自动禁用。
- 点击本周卡片打开详情，再点击某个人名可改判考勤状态。
- **查看日志**：记录管理员与值班账号的操作，按时间倒序显示时间、操作账号、操作内容，可按账号筛选或搜索关键字。覆盖登录、账号增删改、权限与密码变更、排班/特殊排班/每周模板/生成排班/清除排班、调班、考勤与外勤改判、值班签到、外勤登记与确认、系统时间与值班时间设置。
- **数据管理**：左侧列出可访问的数据表与行数，右侧分页预览记录（每页 50 行，支持表内搜索）。可直接编辑或删除单行；只有白名单中的列可写，主键只读。密码、密钥类字段显示为 `••••••`，也无法通过此页修改——改密码请走用户管理。操作日志与出勤归档只允许删除，不允许改写；**站点设置**只能查看和修改值，不能删除整行；**原始管理员（旧版记录）**是只读的历史记录。表名和列名全部来自服务端白名单，请求不会拼进 SQL 标识符。
  - **考勤人员**额外显示所属班次的日期与起止时间（`班次.day` / `班次.start` / `班次.end`），未签到时也能看出这条记录属于哪一班。
  - **多选与批量删除**：点击行内按钮以外的区域即可选中该行（变蓝），按住 Shift 点击可批量选中连续区间；再次点击已选行会取消。底部「清除该页」删除当前页面（含当前搜索条件）的所有行；选中后其左侧出现「清除选中（n）」，取消全部选中后自动消失。两者都需输入确认语，且都会跳过原始管理员。
- **异常统计**（在本周排班下方）：可切换「近 2 周 / 近 4 周」，左右两栏用横向柱状图列出迟到与旷班次数排行，柱右侧标注次数；次数相同按姓名拼音排序。历史不足所选周数时，统计窗口内已有的全部记录。

### 每日 / 每周 / 特殊排班 / 调换值班

- **每日排班**：按日期查看，点击卡片编辑或删除；删除会连同签到记录一起删除。
- **每周排班**：填写四个班次的时间与周一至周日人员，保存后核对勾选；用「下载 CSV 模板」与「一键导入」批量填人。
- **生成排班**：选择开始及截止日期（开始不能早于今天），按星期生成整个区间。已有或冲突班次在无人签到时覆盖，有签到记录时跳过。
- **特殊排班**：新增一次性班次，可在未来特殊排班列表中编辑或删除。
- **调换值班**：选择两位人员和各自的一个未来班次互换，需勾选「双方已协商完成并同意调班」。任一班次开始后不能删除；双方都签到且两个班次结束后，记录自动消失。
- **清除所有排班**：需输入确认语，删除全部班次与签到，保留模板和账号。

### 成员端外勤：登记与确认

- 「外勤管理」：按钮分三档 —— `点击登记`（状态 0）→ `等待确认`（状态 1，黄色）→ `登记完成`（状态 2，浅绿色且锁定）。点击只会从 0 变为 1，不会自动确认。
- 「外勤确认」：列出本月所有状态 1 的登记及登记时间。点「点击确认」变绿后卡片稍后消失、状态变为 2；点「删除」卡片立即消失、状态回到 0，可重新登记。
- 数据库 `field_duty.status` 取值 0/1/2；升级前已有的记录按 2（已确认）处理。

### 用户管理

- 顶部搜索框按姓名即时筛选。
- **补全用户**：在「每周排班」的「保存每周排班」左侧，扫描已保存的每周表及已生成排班（含特殊排班），补建缺失账号。新账号默认加入会员组，初始密码 `gg2017`，已有账号密码保持不变。
- **清理多余用户**：在「添加账号」右侧，确认后删除默认会员组中不在上述排班范围内的账号；其他权限组账号不受影响，排班与签到记录保留。
- 卡片右侧可更改权限、更改密码、重置密码、停用/启用、删除账号。
- 「原始管理员密码」卡片只在原始管理员登录时出现，其他账号即使拥有「其他设置」的全部子项也看不到。
- 「更改权限」弹窗只选择所属权限组；组内访问范围在「权限管理」中通过折叠树维护。

### 外勤管理（管理员）

- 翻页查看各月参与情况，点击人员卡片切换已参加/未参加。只显示已启用且拥有**成员端「外勤管理」**权限的账号，列表人数与已参加人数按该范围统计；撤销权限后隐藏，历史记录保留。
- **月份翻页**：与概览的周排班一致，标题行右侧用箭头查看上个月 / 下个月，范围覆盖有外勤记录的最早到最晚月份（本月始终在范围内）；到边界时对应箭头变灰禁用。离开本月后出现「回到本月」。
- **删除整月外勤**：按钮清空当前显示月份的全部外勤记录（含处于「等待确认」的记录），需输入「删除本月外勤」确认。外勤是每月状态而非归档数据，删除后相关人员回到「未登记」，需重新登记并由他人确认；该月没有记录时按钮自动禁用。
- **只统计已确认（状态 2）的外勤**；自己登记但未确认的记录不计入。
- 管理员修改的条目会显示「管理员修改」。

### 其他设置

- **值班时间**：签到窗口与迟到/旷班阈值。
- **系统时间**：自动或手动时钟，影响签到窗口、统计与时间轴。
- **SMTP 发件邮箱**：填写服务器、端口、加密方式（SSL / STARTTLS / None）、登录账号与密码、发件邮箱与发件人名称。端口留空时按加密方式取默认值（465 / 587 / 25）。密码只保存在服务器配置中，页面不会回显；
  - 密码框留空表示保留原密码，清空存储需要显式提交空值。
  - 启用前必须填好服务器地址与合法的发件邮箱，否则拒绝启用。
  - 「发送测试邮件」会弹窗索取收件地址，用当前配置实际发一封测试信并把成功或失败原因写在卡片内。
  - 实现位于 `server/mailer.py`，仅依赖标准库，每次发送新建连接。`mailer.send(to, subject, body)` 可供其他模块调用。



- 设置提前打卡、迟到、旷班分钟数；旷班时间必须大于迟到时间。
- 系统时间：默认「自动设置」使用真实时间；取消后可指定日期与小时、分钟，并按该时刻开始计时。签到窗口、迟到/旷班判定、概览统计、外勤月份、调班与生成排班全部使用这个时钟，前端时间轴与按钮也会同步。下方始终显示当前系统时间。

### 消息推送

在「消息推送」添加目标邮箱，选择每 1／2／4 周一次及周日发件时间。统计截止北京时间周六 23:59，每次汇总此前连续的完整周日—周六周期。首次启用安排在下一个可用的周日；修改频率或发件时间会重新安排。保存格式、编辑预览均不会发信，默认关闭定时推送；启用前须在「其他设置 → SMTP」完成发件配置。

- 邮件窗口内双击标题、开头或结尾编辑，可用 `{开始日期}`、`{结束日期}`、`{周期周数}`。示例模式仅用于预览，实际发送始终读取真实考勤。
- 迟到／旷班分别启停；关闭后折叠为一行。各自选择名称、次数、日期时间、本月累计迟到次数、分组。日期时间为班次开始时间，多条记录逐行展示，其余列仅在首行填写；月累计按周期结束日所在月份统计，分组为当前权限组。考勤沿用现有迟到／旷班判定和手动改判。
- 短按列名（松开时不足 350 毫秒）切换升序，再按反向；长按 350 毫秒后拖动调整列顺序，关闭的列固定排在启用列之后。键盘可用 Enter 排序、Alt + 左右方向键调序。
- 后台使用真实北京时间，每 30 秒检查一次，需要保持服务运行；手动系统时间不会触发提前发送。重启保留计划与发送记录；停机错过多次时发送最近一次到期的完整周期。每个周期逐邮箱记录发送状态，成功的不重复发送，失败的 15 分钟后重试。异常中断留下的「发送中／待确认」记录不自动重发，以免重复投递。
- 配置与发送记录存储在 `data` 中的应用数据库内；SQLite 与 MySQL 均自动建表，旧库迁移包含投递记录。`消息推送` 为独立权限选项，可在权限组中授权；原始管理员始终可访问。

## 权限组与访问范围

- **权限管理**：点击「新建权限组」输入名称，展开组卡片后用树状折叠选择可访问的页面，点击「保存访问范围」对全组生效。支持重命名和删除自建组；删除后该组账号自动转入「会员」。
- **会员**：内置默认组，所有新增账号（含名单补齐、每周排班生成的账号）默认加入。初始开放成员端「当前排班、外勤管理、外勤确认」三个页面，「排班列表」需要单独授权；访问范围可编辑，组名固定且不能删除。重复启动不重置已保存的选项。
- **用户管理 → 更改权限**：只选择用户所属的一个权限组，不再逐个用户勾选权限选项。账号列表显示所属组。
- **访问选项**与侧栏对应：成员端依次为「当前排班、排班列表、外勤管理、外勤确认」；管理端依次为「概览、每周排班、特殊排班、调换值班、外勤管理、消息推送、用户管理、权限管理、查看日志、数据管理、其他设置」。树采用一行一项的紧凑文件列表，按成员端与管理端缩进折叠，父级支持全选与部分选中。
- **可折叠的子项**：概览下分「查看概览」与「更改考勤状态」；其他设置下分「值班时间」「系统时间」。只勾「更改考勤状态」时概览详情里的人名是只读文本而非按钮，且 `PUT /api/admin/overview/attendance` 只认这一项。
- **「其他设置」没有独立入口**：只要拥有「值班时间」「系统时间」「SMTP」中的任意一项，侧栏就会出现「其他设置」；进入后只显示已授权的那张卡片。三者分别控制 `/api/admin/rules`、`/api/admin/clock`、`/api/admin/smtp`，服务端各自校验。
- 前端隐藏未授权入口，后端逐接口校验组权限；修改组范围会立即影响全组账号的后续请求。管理端的「用户管理」选项覆盖账号、密码与所属组操作；「权限管理」单独决定能否维护组定义。
- **原始管理员**继续从 `data/root_admin.json` 验证，固定拥有全部访问范围，不能在组或用户管理中降权，且不占用组成员数。
- 旧账号的独立权限在升级时转换为对应权限组，保留原访问范围；原权限列只用于兼容迁移，用户有效权限以 `member_accounts.group_id` 对应的 `permission_groups` 记录为准。数据库控制台不能直接修改权限列或所属组。


## 环境要求

- Python 3.10+（建议 3.12）
- MySQL 8.4（默认后端）；SQLite 仅用于迁移兼容与隔离测试

## 配置

运行 `python3 -m server.init_data` 会创建 `data/.env`，按 `.env.example` 生成配置并随机生成两份独立的数据库密码。使用远程数据库时编辑 `data/.env`。环境变量优先于此文件。旧根目录 `.env` 会自动迁移；两处配置不一致时停止并提示合并，不覆盖配置。

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `DB_BACKEND` | `mysql` 或 `sqlite` | `mysql` |
| `MYSQL_HOST` | 数据库地址 | `127.0.0.1` |
| `MYSQL_PORT` | 数据库端口 | `3306`（`.env.example` 中为 Docker 的 `3307`） |
| `MYSQL_DATABASE` | 数据库名 | `gdutnic` |
| `MYSQL_USER` / `MYSQL_PASSWORD` | 应用账号 | — |
| `MYSQL_ROOT_PASSWORD` | 仅由 `compose.yaml` 的本地 MySQL 容器读取，应用本身不用 | — |
| `MYSQL_SSL_CA` | 远程 TLS 证书路径（可选） | — |
| `SESSION_SECRET` | 会话签名密钥（可选，缺省写入 `data/session_secret.txt`） | — |
| `SESSION_HTTPS_ONLY` | 设为 `1/true/yes` 时 Cookie 仅经 HTTPS 发送并启用 HSTS | 关闭 |

本地 Docker 在空的 `data/mysql/` 中自动创建数据库和账号；远程 MySQL 请事先创建数据库并授予应用账号建表与读写权限；应用启动时会自动建表并补齐新增字段，不会覆盖旧数据。

## 启动

使用本地 Docker MySQL：

```bash
python3 -m server.init_data
docker compose --env-file data/.env up -d --wait mysql
./start.sh
```

Windows 使用 `start.bat`。启动脚本会创建项目内 `.venv`、安装依赖（默认 PyPI 失败时自动尝试国内镜像），初始化 `data/` 并读取 `data/.env`，然后监听 `0.0.0.0:50025`。手动运行 uvicorn 或维护命令也会初始化目录。初始化不会重置现有数据库、密码或配置。

启动脚本会先检查数据库，失败时停止并显示连接地址及处理方法。若出现 `Connection refused`，说明配置的数据库地址/端口未接受连接；本地 Docker 部署请先打开 Docker Desktop（Linux 启动 Docker 服务），执行 `docker compose --env-file data/.env up -d --wait mysql`，再启动应用。可单独运行 `.venv/bin/python -m server.check_database` 检查连接（Windows 使用 `.venv\Scripts\python.exe`）。检查会执行应用原有的建表/升级流程，不重置现有数据；不会自动切换数据库。

手动启动：

```bash
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m uvicorn server.app:app --host 0.0.0.0 --port 50025
```

启动后控制台会打印管理员地址（形如 `http://127.0.0.1:50025/a8clrf3j`）。首次打开站点会跳转到该地址创建**原始管理员**；之后的账号在「用户管理」中添加。

### 原始管理员

- **首次初始化时创建一次**，在首次设置页只需填写密码；名称随后固定，之后不会再生成。
- **权限固定且不可更改**：始终拥有全部权限，不受权限编辑影响；不能停用、删除或改名，也没有任何入口能削弱它。
- **不写入 `member_accounts` 表**：账号只存在于 `data/root_admin.json`，因此「用户管理」与数据管理里都看不到这一行，也没有任何操作按钮。启动时会清掉旧版本可能留下的同名镜像行。
- 旧版 `users` 表只是历史记录，不会迁移成第二个可登录账号，也不会删除任何真实值班账号。
- **凭据单独保存在 `data/root_admin.json`**（权限 `0600`，只存哈希），不写入数据库，因此重置数据库不会丢失；登录时也不经过 `member_accounts`。
- 只有密码可以修改：用原始管理员登录后，在「其他设置 → 原始管理员密码」中操作。
- **已有站点升级时**会在下次启动自动创建原始管理员，并在控制台打印一次性初始密码；用它登录后立即修改即可。
- 改名只需编辑 `data/root_admin.json` 的 `username` 字段（密码哈希保持不变）；该文件就是唯一事实来源。

启动时还会为每周名单及已排班人员补齐缺失账号，也可单独执行：

```bash
.venv/bin/python -m server.provision_members
```

给指定账号补授全部权限（管理员恢复用）：

```bash
.venv/bin/python -m server.grant_admin <账号名>
```

## 数据与备份

- **业务数据**保存在 MySQL；本地 Docker 将 `data/mysql/` 挂载到容器 `/var/lib/mysql`，不再使用命名卷。已有命名卷部署应先导出 SQL 到 `data/backups/`，启动新的空库后导入；不要直接复制运行中的 MySQL 文件。
- 项目 `data/` 保存运行时文件，**不提交到 Git**：
  - `.env`：数据库凭证与本地配置；
  - `mysql/`：本地 MySQL 数据、证书与日志；
  - `mysql-config/runtime.cnf`：按本地文件系统大小写规则生成的 MySQL 配置；
  - `logs/`：QQ 机器人等运行日志；
  - `session_secret.txt`：会话签名密钥；
  - `weekly_roster.json`：每周名单种子（仅在没有已保存模板时读取）；
  - `imports/`：排班表与 CSV 模板等导入文件；
  - `app.sqlite`、`backups/`：旧版 SQLite 与迁移备份。
- 首次初始化创建 `data/`、配置及 `mysql/`、`mysql-config/`、`imports/`、`backups/`、`logs/`、`certs/` 子目录。SQLite 表和会话密钥按需创建；不生成包含真实人员的种子名单。
- SQL 导出统一放在 `data/backups/`，证书放在 `data/certs/`。`MYSQL_SSL_CA` 的相对路径相对于 `data/`。备份 MySQL 使用逻辑备份（如 `mysqldump`），或停库后备份 `data/mysql/`。
- `sql/mysql_schema.sql` 只有建表结构，保留在源码中；`.env.example` 只有占位配置。Git 忽略整个 `data/`，并额外忽略数据库文件、SQL 导出、私钥、证书及人员表格，防止误放到其他目录后被提交。

## 从 SQLite 迁移

先停止旧版应用写入 SQLite，配置好**空的** MySQL 数据库，再执行：

```bash
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m server.migrate_mysql --source data/app.sqlite
.venv/bin/python -m server.provision_members
```

迁移会先备份 SQLite 到 `data/backups/`，再在单个 MySQL 事务中导入并逐表校验，保留密码哈希、班次 ID 与签到时间。目标库非空时停止，任何失败都会回滚。迁移完成后再启动新版服务。

## 安全

- 登录通过 `fetch` 发送 JSON，表单强制 POST；即使脚本未加载，密码也不会出现在网址栏或访问日志中。
- 会话与管理员 Cookie 有效期 4 小时；同一来源连续 8 次登录失败会限制 15 分钟。
- 登录接口只信任直连地址，不读取可伪造的 `X-Forwarded-For`。
- 已设置禁止页面被嵌套、禁止外链脚本、不发送 Referer、禁止 MIME 嗅探等响应头。
- 公网部署请使用 HTTPS，并设置 `SESSION_HTTPS_ONLY=1`。
- 本项目未内置 WAF 与限流之外的防护，公网部署建议放在反向代理之后。
